自定义搜索引擎

  • 名称

    简称，中英文都可，比如 Google 或者 谷歌，设置的图标样式没有自定义时默认会显示名称的第一个字（通过 CSS 实现，如发现在个别网页错误建议反馈以修正）。

  • 图标 CSS class

    可使用内置图标，或在自定义样式设置中写好样式，在此填上 class 名称。

  • 网址

    访问网址，怎么访问根据类型决定。可使用以下变量：

    • %s 或 ${query}
      以网址参数形式编码的搜索词
    • %p 或 ${paged}
      页码
    • ${hostname}
      当前页面的网址域名，配合搜索词可实现站内搜索，如：?q=site%3A${hostname}+${query}
    • ${num}
      页面结果条数
    • ${first} 或 ${index}
      用于翻页参数，值是 (${paged}-1)*${num}，如果 ${num} 未指定则以10代替，以此计算出来的结果第一页是0，第二页是10，第三页是20，以此类推
    • ${start}
      用于翻页参数，值是 ${first}+1，计算出来的结果第一页是1，第二页是11，第三页是21，以此类推

  • 类型

    访问网址，怎么访问根据类型决定。可使用以下变量：

    • AJAX 数据接入

      需返回指定格式 JSON 数据，若有 page_items 则会遍历生成 HTML 列表，若有 body 则直接作为 HTML 代码插入，可根据自己需求返回页面代码。

      请注意：部分网站 CSP 禁止加载第三方图片（包括 DATA URL），如通过 body 返回 HTML 代码，请将 HTML 代码中所有 img 标签的真实图片路径添加到 data-src 属性，src 改为占位图片，扩展将通过不受网站 CSP 和图片 CORS 影响的 Backgroud Script 为您加载图片。图片加载后需转换为 DATA URL 嵌入，为减少性能需求，请确保图片是压缩后的缩略图。

      此模式支持 Google Custom Search JSON API，网址格式参考： https://www.googleapis.com/customsearch/v1?key=接口密钥&cx=自定义搜索引擎ID&q=${query}&start=${start}&gl=countryCN

    • DOMParser 解析
      此格式可请求普通网页，但需要指定一个 DOMParser 函数，将网页 HTML 处理成 AJAX 数据格式以供渲染。扩展内置了两个函数以供参考，请看 DOMParser JSON 设置 页面。
    • iframe 内联
      在打开的小窗通过 iframe 内嵌目标网址，优点是配置简单使用成本低，缺点是支持 iframe 而且页面排版能在小窗展示的网站不好找，目前知道的只有百度移动搜索。此外部分网站设置了 content-security-policy 头会导致无法 iframe 加载其他网站网页，我看的有扩展通过 webRequest 将这个参数去掉了让 Chrome 不执行安全策略来解决这个问题，本扩展目前不考虑这样做，因为不建议 iframe 内联。
    • 新标签页打开
      点击搜索图标或链接会在打开一个新标签页

  • （添加到）悬浮图标

    划词后是否显示这个搜索引擎图标。如果悬浮搜索图标选择了不显示图标，则所有的不会显示。

  • （添加到）右键菜单

    将当前搜索引擎添加到右键菜单。受 Chrome 限制，如只开启一个则会在右键一级菜单，如开启多个就会收纳到二级菜单。如有个别重度使用的搜索引擎，则建议只开启那一个，可快速使用。

DOMParser JSON 配置

由于 CSP 限制，部分网页无法插入动态脚本，因此通过配置 Selectors 的方式实现自定义解析。JSON 配置第一级每一项相当于一个函数，名称是函数名，子项是解析需要的各类内容选择器或提供转换服务的接口网址。

Selectors 模式：每类内容支持指定多个选择器，从上往下，匹配到为止。细项 name 指 querySelector 是使用的选择字符串，property 指匹配内容的属性名，同时还支持 excludeNodes 指定需要移除的元素选择器，可用于移除可能干扰选择的元素。

transServer 模式：扩展会向 transServerUrl 提交 POST 数据格式为 {"requestURL": "当前查询的搜索引擎链接", "responseHTML": "搜索引擎链接返回的HTML内容"}，服务端需返回 AJAX JSON 格式数据，即包含 page_items 数组或 body 字符串的 JSON 格式数据。

各模式运行流程介绍

新标签页打开

划词选中 > 触发功能 > 根据搜索参数创建 URL > 在新标签页中打开 > 展示内容

优点：配置简单，无兼容性问题。

缺点：与右键菜单搜索一样，没有小窗的便捷性。

iframe 内联

划词选中 > 触发功能 > 根据搜索参数创建 URL > 通过 iframe 标签加载 > 展示内容

优点：配置简单。

缺点：常见搜索引擎页面没有专门的PC小窗页面，可用性较差。且受 CSP 影响，部分网页无法加载。

AJAX 数据接入

划词选中 > 触发功能 > 根据搜索参数创建 URL > 在扩展后台（浏览器客户端本地后台，非服务端）fetch URL 获得数据 > 按 JSON 数据生成 HTML > 展示内容

优点：格式化数据，展示稳定，无兼容问题。

缺点：需自行适配目标搜索引擎。

DOMParser 解析（Selectors）

划词选中 > 触发功能 > 根据搜索参数创建 URL > 在扩展后台（客户端本地）fetch URL 获得 HTML 内容 > 根据 Selectors 匹配内容，生成 AJAX 需要的格式 > 按 JSON 数据生成 HTML > 展示内容

优点：目标搜索引擎是 PC 网页也可适用，无需自行转换格式，本地 fetch URL 时与在新标签页中请求一样携带 Cookies，因此搜索结果可跟随账号设置。

缺点：当目标网页改版时需改动 Selectors 配置以适应；无法在小窗内适配网页验证页面，需要稳定的使用体验，请在目标搜索引擎网页登录账号以及使用稳定的网络环境。

DOMParser 解析（transServer）

此模式所发送的内容虽未涉及 Cookies，但登录后网页 HTML 仍可能涉及隐私内容，因此限定 Server URL 必须为本地地址。请勿使用任何第三方服务，如需使用私人云服务器处理请在本地搭建 HTTP 转发。

划词选中 > 触发功能 > 根据搜索参数创建 URL > 在扩展后台（客户端本地）fetch URL 获得 HTML 内容 > 将 HTML 通过 POST 发送给 trans Server（服务端） > 按返回 JSON 数据生成 HTML > 展示内容

优点：相比 AJAX 适配接入，DOMParser 通过浏览器本地真实环境请求目标网页，不易触发风控；相比 DOMParser Selectors 模式，transServer 模式拥有 Selectors 的真实请求优点，并可以自行编写处理 HTML 内容的代码，完全控制展示内容。

缺点：需要自行编写和维护转换服务。
